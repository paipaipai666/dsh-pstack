## Obstacles

- **`vp check` cannot run on this host.** Formatting succeeds (`All 146 files are correctly formatted`) and then lint panics before analysis starts:
  ```
  error: Linting could not start
  thread 'tokio-rt-worker' (…) panicked at crates/oxc_allocator/src/pool/fixed_size.rs:112:67:
  called `Result::unwrap()` on an `Err` value: ()
  ```
  It reproduces on the pristine HEAD with a stashed working tree, so it is environmental (most likely the 2-core / ~2 GB host), not a symptom of the sync. `UV_THREADPOOL_SIZE=1` and an isolated `vp lint` make no difference. **Lint is therefore unverified locally**; the GitHub Actions gate is the only lint evidence. Run `fmt`, `typecheck`, and `test` separately to recover the rest of `vp check`, and say so explicitly rather than reporting `vp check` as passed.

- **Three tests fail until `dist/` exists.** `tests/package-name.test.ts`, `tests/script.test.ts`, and `tests/skill-catalog.test.mjs` read `dist/client.js`, `dist/pstack/skills/…`, and the translated skill catalog; on a fresh checkout they fail with "run `vp run build` first". Run `vp run build` before `vp test`. After the build all 30 files / 244 tests pass. This is documented only inside the test failure messages.

- **The submodule clone is shallow (depth 1).** `git diff <prev-commit> HEAD` fails because the previous baseline commit is absent, and `git log` shows one commit, which makes an unchanged-looking upstream tree look already-synced. Fetch the parent first (`git fetch --depth=2 origin <sha>`) before trusting the diff, otherwise a new baseline cannot be checked for real port-relevant changes. `git fetch` alone adds no working-tree diff, but it does grow `.git/modules/upstream/cursor-plugins`.

- **`vpx port/release-compatibility.ts` reports "Updated …" even when nothing changed.** The message is printed on every run; check `git status` or the `--check` mode to tell whether a row actually moved.

## Better approaches

- **Start with the lock and audit checks, not with a rebuild.** `vpx port/scan.mjs --check-lock` and `--check port/audit.md` (224 references) decide in seconds whether the port side already matches the target baseline. When both pass and `generate:check` is clean, the remaining work is verification, and the audit can be limited to the upstream diff rather than a full re-review.

- **Review the upstream diff by theme, not file by file.** The 0.15.42 delta is dominated by the one-file rewrite of `how` and `why` (about 1,000 deleted reference lines) and a new default-model set (`claude-fable-5-2-*`, `gemini-4-carbon-high`, `claude-opus-5-5-high-fast`), plus the `# defaults: 2` setup marker and statechart renderer/SANY fixes. Checking those four themes against `src/role-manifest.ts`, `src/native-text.ts`, `port/overrides/`, and `port/patches/` covers the port surface; the rest is prose.

- **Do not copy upstream's setup-pstack migration into the override.** Upstream's new step rewrites old Claude slugs and defaults, but the DSH port writes `inherit-parent` for every role by default, so applying that migration would overwrite the user's real routes. The override already declines it; keep it that way on the next bump.

- **`how`/`why` retirement needs no DSH decision.** Those roles were never in the DSH role manifest, so retiring `how explorer`, `how explainer`, `why investigators`, and `why synthesizer` upstream has no DSH counterpart and is not a product decision.

## Harness

- **Noise on every command.** Each shell call prints `landlock-run: partial enforcement (older Landlock ABI)` to stderr (apparent typo for "enforcement"). It is harmless but ends up in captured output; filter it before treating stderr as a failure signal.
- **`git stash -u` around a read-only probe is a risk worth avoiding.** Stashing the tree to prove the lint panic was pre-existing was safe here only because the tree was clean. On a task with uncommitted work, prove environmental failures another way, for example by checking whether the touched paths can reach the failing tool at all.
- **Sandbox writes.** Files under the session workspace and `.git` are writable; this log was written as the only change and no git command was run.
